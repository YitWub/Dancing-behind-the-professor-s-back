# B필러 — 꿀강 탐색 + LLM 신뢰성 평가

> 답하는 질문: **"이 강의 들어도 되나?"**
> 핵심 주장: **별점 평균으로는 이 질문에 답할 수 없다.**

---

## 1. 문제 정의

에브리타임식 별점 평균의 실패 사례는 전부 같은 모양이다.

- 강의평 **4건**인데 평균 4.8 → "꿀강 1위"
- 1점과 5점만 있고 3점이 없는데 평균 3.0 → "평범한 강의"
- **2021년** 강의평 5건이 마지막인데 그 평균이 아직 1위
- **학점 잘 받은 사람만** 후기를 써서 평균이 위로 떠 있음

넷 다 "평균이 틀렸다"가 아니라 **"평균을 믿을 근거가 없다"** 는 문제다.
그래서 이 필러는 점수를 계산하기 전에 **신뢰성부터 판정한다.**

---

## 2. 파이프라인

```
data/reviews.seed.json (강의평 원본)
      ↓  axes.ts        5축 추출        ← LLM 또는 키워드 휴리스틱
      ↓  reliability.ts 신뢰성 판정     ← 5가지 편향 신호
      ↓  score.ts       베이지안 축소   ← 신뢰도가 낮으면 50 쪽으로 끌어당김
      ↓  summary.ts     3줄 요약
data/lectures.json (빌드 산출물) → 앱은 이것만 읽는다
```

**런타임에 API 키가 필요 없다.** `scripts/score-lectures.ts` 가 빌드 타임에 한 번 굽고,
앱은 `data/lectures.json` 만 읽는다. 키 없이도 `npm run build` 와 데모가 돌아간다.

## 3. 5축 (`HoneyAxes`)

| 축 | 의미 | 높을수록 꿀? |
|---|---|---|
| `gradeGenerosity` | 학점 후함 | ✅ |
| `workload` | 과제/팀플 부담 | ❌ |
| `attendanceStrictness` | 출결 빡셈 | ❌ |
| `teachingQuality` | 강의력 | ✅ |
| `examDifficulty` | 시험 난이도 | ❌ |

**언급이 없는 축은 0.5 로 둔다.** 0.5는 "중간"이 아니라 **"모른다"** 는 뜻이다.
휴리스틱은 키워드가 0회 잡히면 별점 보정조차 하지 않고 정확히 0.5를 준다.
LLM 에게도 같은 규칙을 강제하고(`unknown` 배열), 돌아온 값을 0.5로 되돌린다.

## 4. 신뢰성 판정 (`ReliabilityVerdict`) — 이 앱의 심장

### 4-1. 5가지 신호와 감점

| flag | 판정 조건 | 감점 계수 |
|---|---|---|
| `SMALL_SAMPLE` | 강의평 < 8건 | 별도 계수 없음 — 아래 표본 곡선으로 연속 반영 (이중 감점 방지) |
| `POLARIZED` | 1~2점 + 4~5점 비중 ≥ 80% **이면서** 양쪽 꼬리가 각각 ≥ 25% | ×0.80 |
| `STALE` | 최근 강의평이 2년 이상 전 | ×0.75 |
| `PROFESSOR_CHANGED` | 교수 변경 이력 존재 | ×0.70 |
| `SELF_SELECTION` | 학점을 밝힌 사람(≥5명) 중 A 계열 비중 ≥ 70% | ×0.85 |

**표본 신뢰도 곡선**: `sampleFactor = n / (n + 4)`

| n | 4 | 8 | 12 | 20 | 40 |
|---|---|---|---|---|---|
| sampleFactor | 0.50 | 0.67 | 0.75 | 0.83 | 0.91 |

`score = sampleFactor × (해당되는 flag 들의 계수 곱)`

곱셈인 이유: 신호가 겹치면 신뢰도가 **빠르게** 떨어져야 한다.
"강의평 5건 + 2022년이 마지막" = 0.56 × 0.75 = **0.42 (낮음)**.

`band`: `≥0.7` 높음 / `≥0.45` 보통 / 그 미만 낮음.

### 4-2. `POLARIZED` 에 조건이 두 개인 이유

"극단 비중 80% 이상"만 보면, 전원이 5점을 준 만장일치 명강의도 극단으로 잡힌다.
그래서 **양쪽 꼬리가 각각 25% 이상**일 때만 플래그한다. 호불호가 갈리는 것과
다들 좋아하는 것은 전혀 다른 상황이고, 전자만 평균이 무의미하다.

### 4-3. LLM 이 지적한 우려는 근거로만 쓴다

LLM 이 `concerns` 로 추가 편향을 지적하면 `reasons` 에 `"LLM 지적: …"` 으로 노출하되,
**점수는 깎지 않는다.** 규칙 기반으로 검증 가능한 신호만 감점한다.
"LLM이 그렇게 느꼈다"는 이유로 숫자를 흔들면 그것 자체가 false precision 이다.

## 5. 꿀강 지수와 축소 계수 k

### 5-1. 원점수

```
rawScore = 100 × ( 0.35·학점후함
                 + 0.20·(1−과제량)
                 + 0.15·(1−출결빡셈)
                 + 0.20·강의력
                 + 0.10·(1−시험난이도) )
```

가중치 근거: 목표가 **"학점 잘 주면서 꿀강"** 이므로 학점 후함이 가장 무겁다(0.35).
강의력과 과제량이 그다음(각 0.20). 출결은 시간표로 회피 가능해서 0.15,
시험 난이도는 학점 후함과 상관이 높아 중복을 피하려고 0.10.

### 5-2. 베이지안 축소 — **이 필러에서 가장 중요한 식**

```
honeyScore = (n_eff × rawScore + k × 50) / (n_eff + k)

n_eff = reviewCount × reliability.score      ← 신뢰도로 깎인 "유효 표본"
k     = 12 (SHRINKAGE_K)
```

**k = 12 의 근거**

`k` 는 "원점수와 중앙값 50을 반반 믿는 지점"이다. `n_eff = k` 일 때 정확히 절반씩 섞인다.

- 신뢰도 1.0짜리 강의가 `n_eff = 12` 가 되려면 강의평이 **12건** 필요하다.
  이 데이터셋의 강의평 수 중앙값이 17건이므로, **중앙값보다 조금 아래**를 반반 지점으로 잡은 셈이다.
- 즉 "평균적인 강의는 자기 점수를 60% 정도 주장할 수 있고,
  표본이 중앙값보다 한참 적은 강의는 주장 지분이 빠르게 줄어든다."
- k를 더 키우면(예: 30) 강의평 31건짜리도 50 근처로 뭉개져 순위 자체가 무의미해지고,
  더 줄이면(예: 4) 4건짜리가 다시 상위권으로 튀어 올라온다. 12는 그 사이다.

**의뢰서의 문제 상황을 이 식에 넣어보면:**

> 강의평 4건, 신뢰도 0.45, 원점수 87점

```
n_eff = 4 × 0.45 = 1.8
honeyScore = (1.8×87 + 12×50) / (1.8+12) = 756.6 / 13.8 ≈ 55
```

**87.3점 1위 → 55점 + "표본 부족" 배지.** 이게 이 식이 하는 일 전부다.

### 5-3. 실제 결과 — 정렬 방식만 바꿔 비교

| 별점 평균 순 (축소 없음) | 꿀강 지수 순 (축소 적용) |
|---|---|
| 1. 스포츠와건강 4.11 (n=18) | 1. 파이썬프로그래밍 **69** (n=31) |
| 2. 파이썬프로그래밍 4.03 (n=31) | 2. 과학기술의철학적이해 **69** (n=29) |
| 3. 인공지능과사회 3.88 (**n=8**) | 3. 한양인의삶과비전 **66** (n=26) |
| 4. **세계의음식문화 3.83 (n=6, SMALL_SAMPLE)** | 4. 데이터베이스시스템 **65** (n=21) |
| 5. 한양인의삶과비전 3.81 (n=26) | 5. 심리학개론 **61** (n=25) |

왼쪽에선 강의평 6건짜리가 4위다. 오른쪽 상위권은 전부 n ≥ 21 · 신뢰도 high.
`GET /api/lectures?sort=rating` 으로 왼쪽을, `?sort=honey` 로 오른쪽을 그대로 재현할 수 있다.
(발표 때 이 둘을 나란히 띄우는 게 이 필러의 데모다.)

### 5-4. 점수를 단독으로 쓰지 않는다

`honeyBandLabel()` 이 점수 옆에 붙일 말을 준다.
축소가 60% 이상 걸렸으면 `"표본이 적어 평균 쪽으로 크게 보정됨"` 이 우선한다.
숫자만 크게 띄우지 말 것 (CONTRACT.md 정직성 1·3번).

## 6. LLM 연동

### 6-1. 오프라인 파이프라인

```bash
node scripts/make-seeds.ts        # 시드 생성 (결정론적)
node scripts/score-lectures.ts    # 키 있으면 LLM, 없으면 휴리스틱
node scripts/score-lectures.ts --heuristic  # 강제 휴리스틱
node scripts/score-lectures.ts --verify     # 휴리스틱 정확도 검증
```

호출 경로는 2단계다. `package.json` 수정이 금지돼 있어서(팀 규약) 둘 다 둔다.

1. `@anthropic-ai/sdk` 가 설치돼 있으면 **공식 SDK**
2. 없고 `ANTHROPIC_API_KEY` 만 있으면 `POST https://api.anthropic.com/v1/messages` 직접 호출
3. 둘 다 없으면 → **휴리스틱 폴백**

모델은 `claude-sonnet-5` (환경변수 `ANTHROPIC_MODEL` 로 변경 가능).

### 6-2. 프롬프트 설계

시스템 프롬프트(`AXES_SYSTEM_PROMPT`)는 **모든 강의에 대해 완전히 동일한 문자열**이다.
날짜·난수를 넣지 않아서 prompt caching 이 그대로 먹는다 (`cache_control: ephemeral`).
강의별로 달라지는 부분은 user 메시지에만 들어간다.

프롬프트에 박아둔 규칙 4개:

1. **언급 없으면 0.5 + `unknown` 에 기입.** "근거 없이 숫자를 지어내지 마세요. 모른다가 틀린 숫자보다 낫습니다."
2. 소수 의견이 아니라 **전체 중심 경향**을 볼 것
3. `summary` 는 정확히 3줄, 각 40자 이내, 표본이 적으면 그 사실을 한 줄에
4. `concerns` 에 이 강의평을 믿기 어려운 이유 (없으면 빈 배열)

### 6-3. 폴백이 진짜로 동작하는가 — 3중 방어

| 실패 지점 | 대응 |
|---|---|
| 키·SDK 없음 | 전체를 휴리스틱으로 (콘솔에 명시) |
| 특정 강의에서 API 예외 | **그 강의만** 휴리스틱으로, 나머지는 LLM 유지 |
| 응답 JSON 이 깨짐/범위 밖 | `parseLlmAnalysis()` 가 `null` 반환 → 그 강의만 휴리스틱 |

어느 경로를 탔는지는 강의마다 `reliability.reasons` 에 남는다
(`"축 추출: LLM 분석"` / `"축 추출: 키워드 휴리스틱 (LLM 미사용)"`).
UI 배지로 그대로 쓰면 된다.

### 6-4. 휴리스틱은 얼마나 쓸 만한가

시드 강의평은 "진짜 축 값"에서 생성했으므로 정답을 안다.
`--verify` 로 휴리스틱 추출값과 정답의 상관계수를 잰다 (강의평 8건 이상인 23개 강의 기준):

| 축 | 상관계수 r |
|---|---|
| `examDifficulty` | 0.93 |
| `attendanceStrictness` | 0.87 |
| `workload` | 0.79 |
| `gradeGenerosity` | 0.76 |
| `teachingQuality` | **0.56** |

시험/출결처럼 표현이 정형화된 축은 키워드만으로 잘 잡힌다.
**강의력(0.56)이 약한 게 LLM 이 필요한 이유다** — "교재만 읽으신다", "진도가 빠르다" 처럼
같은 뜻을 문장 구조로 돌려 말하는 경우가 많아 사전으로는 한계가 있다.

> 주의: 이 검증은 **우리가 만든 시드**를 상대로 한 것이라 상한선에 가깝다.
> 실제 강의평에서는 더 낮게 나올 것이다. 이 수치를 "휴리스틱 정확도"라고 일반화하지 말 것.

`--verify` 는 콘솔 출력과 함께 **`data/honey-verify.json`** 을 떨군다 (발표 슬라이드용).

```
axes[]       축별 상관계수 r, 대상 강의 수
perLecture[] 강의별 { truth(진짜 축), extracted(추출 축), keywordHits(축별 키워드 적중 수) }
caveat       위의 "상한선에 가깝다" 단서가 파일 안에도 박혀 있다
```

`perLecture` 로 truth vs extracted 산점도를 그리면 teachingQuality 만 유독 퍼지는 게 보인다.

### 6-5. 모듈 안전성

`axes.ts` / `reliability.ts` / `score.ts` / `summary.ts` / `pipeline.ts` 는 전부 **순수 모듈**이라
클라이언트 컴포넌트에서 import 해도 된다. `node:fs` 를 쓰는 건 **`store.ts` 하나뿐**이다.
`FLAG_LABELS`, `BAND_LABELS`, `AXIS_LABELS`, `honeyBandLabel()` 전부 클라이언트에서 안전하게 쓸 수 있다.

## 7. 강의평 데이터 출처 — 정직하게

**`data/reviews.seed.json` 은 전부 가상 데이터다.**

- 에브리타임 등 실제 강의평 사이트는 **로그인·ToS 문제로 크롤링하지 않았다**
- 강의명은 ERICA 개설과목 계열을 참고했으나 **교수명과 강의평 본문은 전부 창작**이다
- 강의 27개 / 강의평 455건, `scripts/make-seeds.ts` 로 고정 시드에서 재생성 가능

이 사실은 **모든 강의의 `reliability.reasons[0]`** 에 박혀 있다:
`"데이터 출처: 시드(가상) 강의평 — 실제 수집 데이터가 아닙니다"`

## 8. 화면(팀원3)이 반드시 표시해야 할 것

1. **전역 배지**: "시드(가상) 강의평 기반" — `reliability.reasons[0]` 을 그대로 쓰면 된다
2. `reliability.flags` 별 칩: 표본 부족 / 호불호 갈림 / 오래된 강의평 / 교수 변경 / 상방 편향 의심
   (`FLAG_LABELS` 에 한국어 라벨 있음)
3. `honeyScore === null` (강의평 0건) → 숫자 자리에 **"판단 불가 — 강의평 없음"**
4. `honeyScore` 는 `honeyBandLabel()` 문구와 **항상 같이** 표시. 숫자만 크게 띄우지 말 것
5. `axes` 값이 정확히 `0.5` 인 축은 "중간"이 아니라 **"언급 없음"** 으로 흐리게 처리
