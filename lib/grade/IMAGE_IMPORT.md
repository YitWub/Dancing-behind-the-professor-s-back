# 평가비율 이미지 입력 — OCR 우선·Gemini 보조

## 사용자 흐름

1. 과목 추가/설정에서 **이미지 선택 · OCR로 읽기**를 누르거나 캡처 붙여넣기 영역에서 Ctrl+V를 누른다.
2. 기본 인식은 브라우저 Tesseract.js OCR이다. API 키가 없어도 사용할 수 있으며 이미지는 서버로 보내지 않는다.
3. 결과의 이름·비율·합계를 원본과 비교한다. 누락·오독은 직접 고칠 수 있다.
4. OCR이 읽지 못했거나 결과가 다르면 **Gemini로 다시 분석**을 선택한다. 이 버튼을 누를 때만 이미지를 Google Gemini로 보낸다. 자동 외부 전송·자동 재시도는 하지 않는다.
5. Gemini 키·모델 설정이 없으면 재분석 버튼만 비활성화된다. OCR·검토·수동 입력은 계속 사용할 수 있다.
6. 기존과 동일한 검증을 통과한 뒤 **이대로 적용**을 눌러야 과목 초안에 반영된다. 기존 과목 자동 저장/신규 과목 등록 절차는 그대로다.

## 클라이언트 OCR

- `components/grade/AssessmentImageImport.tsx`: 선택/붙여넣기, 전처리, 진행·취소, Gemini 재분석, 기존 검토/적용 흐름.
- `components/grade/assessment-ocr-client.ts`: 이미지 선택 후에만 `tesseract.js` 7.0.0을 동적으로 가져온다. 한국어+영어, 단일 텍스트 블록 모드다.
- `lib/grade/assessment-ocr.ts`: OCR 문자열을 기존 `ImageExtraction` 형태로 변환하는 순수 함수다. 외부 라이브러리/서버 모듈을 import하지 않는다.
- 초기 OCR 실행에는 jsDelivr의 worker/WASM/한국어·영어 언어 데이터 다운로드를 위한 인터넷 연결이 필요하다. 인식용 라이브러리·언어 파일을 내려받지만 이미지는 전송하지 않는다.
- OCR 실행은 최대 90초로 제한한다. 취소·재선택·화면 이탈 시 작업을 중단하고 늦게 돌아온 결과를 무시한다.

PNG/JPEG/WebP 3MiB 이하를 실제 디코딩한 뒤 최대 2천 픽셀, 작은 캡처는 최대 2배로 확대한다.
원본의 2천만 픽셀/한 변 8천 픽셀 제한은 유지한다. 흰 배경에 JPEG로 재인코딩하여 메타데이터를 제거한다.
같은 전처리 이미지를 OCR과 선택적인 Gemini 재분석에서 사용한다.

`항목 비율%` 줄과 `항목명 / 다음 줄 비율%`를 읽는다. 합계·등급 행은 제외하고 0%는 보존한다.
실제 캡처에서 관찰된 `% → 96` 오독은 보정하되 확인 필요 표시를 남긴다.
109%처럼 범위를 벗어난 값, 09%처럼 의심스러운 숫자, 낮은 OCR 신뢰도도 버리지 않고 검토 대상으로 표시한다.
합계 부족·중복·여러 열의 비율 등은 기존 검증으로 보류한다. 누락 비율을 추측하거나 100%로 자동 정규화하지 않는다.

OCR은 줄 단위 인식이므로 복잡한 열·계층·세부 배점 의미를 확실히 해석하지 못할 수 있다.
합계가 맞아도 항목명·비율이 정확하다는 보장은 없다. 결과를 원본과 대조하고 필요하면 Gemini를 선택한다.

## 선택 기능: Gemini 재분석 활성화

프로젝트 루트의 `.env.example`을 참고해 `.env.local`의 `GEMINI_API_KEY`와 `GRADE_VISION_MODEL`을 설정하고 서버를 다시 시작한다.
기존 파일은 덮어쓰지 않는다. OCR만 사용할 때는 설정할 필요가 없다.
키는 서버에서만 사용하며 `NEXT_PUBLIC_` 접두사를 붙이지 않는다.

기존 승인 경로 `app/api/grade/assessment-image/route.ts`와 `lib/grade/assessment-image-server.ts`를 그대로 사용한다.
키·모델 준비 상태 GET만 이미지 선택 전에 확인한다. 준비 상태는 실제 키 유효성/공급자 접근 권한 검증이 아니다.
사용자가 재분석 버튼을 눌러야 POST가 발생한다. OCR 결과가 있어도 다른 해석을 원하면 재분석할 수 있다.
Gemini 실패·취소 시 기존 OCR 미리보기는 남겨 수동 수정할 수 있다.

서버의 기존 동작을 유지한다:

- 허용 모델 확인, 같은 출처, 본문 크기·MIME·파일 시그니처 검증.
- JSON Schema 구조화 응답과 `parseImageExtraction` 검증. 여러 표/평가표 없음/판독 불가 상태를 구분한다.
- 공급자 호출 30초 제한. 클라이언트는 35초에 대기 중단.
- 서버 인스턴스당 분당 최대 10회, 동시 2회. 공급자 429의 Retry-After를 존중하며 자동 재시도하지 않는다.
- 다른 모델로 자동 대체하지 않으며 API 키·원본·응답 원문을 로그/브라우저에 반환하지 않는다.

Google 프로젝트의 접근 가능한 모델·사용량·무료/유료 정책은 공급자 설정에 따른다.
재분석 이미지는 Google에 전송되며 무료 등급에서는 서비스 개선에 사용될 수 있다는 기존 안내를 유지한다.
개인정보 없는 평가표만 사용한다. 공급자 측 처리·보관/비용을 앱에서 보장하지 않는다.

## 기존 기록 보존

검토·적용은 `assessment-image.ts`의 기존 `buildWeightPreview`, `validateWeightPreview`, `applyWeightPreview`를 공유한다.
OCR이나 Gemini 중 어느 쪽이든 같은 이름이 명확하게 연결될 때만 기존 ID·시험 점수·과제 그룹·통계·출석 연결을 보존한다.
사진에 없는 미기록 기본 항목은 제외하며, 실제 기록/과제/명시적 출석 연결은 0%로 보관한다.
주차학습·학습참여도를 임의로 출석으로 분류하지 않는다.
세부 항목의 내부 비율은 최종 비율로 추측하지 않으며 Gemini가 추출한 계층은 기존 검증에서 중복 합산을 막는다.

원본 이미지·OCR 원문·미리보기는 localStorage나 서버 파일에 저장하지 않는다.
인식 중 수정·오류·취소는 과목 원본을 바꾸지 않는다. 적용 후에만 기존 확인·저장 흐름으로 넘어간다.

## 검증

- `lib/grade/__tests__/assessment-ocr.test.ts`: 한국어/전각/소수/줄바꿈, 0%, 합계 제외, 실제 오독, 중복·저신뢰도·누락 검토, 확인 전 적용 차단.
- 기존 `assessment-image.test.ts`: Gemini 요청·응답·제한·실패와 기존 점수/과제/출석 보존.
- API 키 없는 브라우저에서 실제 캡처의 6개 항목·합계 100%, 보정 검토 후 적용 활성화, Ctrl+V 및 진행 취소를 확인한다.
- 실제 Gemini 호출은 유효한 키·모델 설정이 있어야 별도로 확인할 수 있다. 가짜 인식 결과를 실제 분석으로 표시하지 않는다.
