## 과목 편집 자동 저장

강의계획서 캡처로 평가비율을 입력하는 서버 설정·검토·데이터 보호 규칙은
[IMAGE_IMPORT.md](./IMAGE_IMPORT.md)를 참고한다. 사용자 적용 전에는 기존 데이터를 변경하지 않는다.

기존 과목의 기록·설정은 유효한 편집값을 먼저 공유해 HP바·전망·목표 플래너를
실시간으로 갱신한다. 실제 저장 완료와는 별개다. `CourseEditor`는 마운트를 유지하고
선택·출결 버튼은 0ms, 숫자·문자 입력은 450ms 대기 후 최신 편집만 저장한다.
`autosave.ts`의 단일 대기열은 이전 작업을 취소하며 저장 자체는 동기 localStorage 쓰기다.
검증 실패나 확인이 필요한 구조 변경은 저장을 보류한다. 자동 비율 재배분은 하지 않는다.

공식 데이터는 기존 `erica.grade.courses.v2` 형식과 snapshot 충돌 검사를 그대로 쓴다.
v1 이전은 자동 실행하지 않고 기존의 명시적 검토·확인을 유지한다. 신규 과목은
등록 확인 후 기존 과목 자동 저장 흐름에 들어간다. 과목 삭제와 과제 구조·배점 변경은
확인 대상이며 일반 출결 횟수 정정은 자동 저장할 수 있다.

비율 110%, 빈 점수 등 편집 중간 상태는 공식 문서에 쓰지 않는다. 대신 과목 ID별
`erica.grade.editor-draft.v1.<id>`에 입력 문자열과 기준 과목을 보관해 새로고침 후
편집을 복원한다. 숫자 NaN도 빈 입력 의미를 잃지 않게 보존한다. 기준 과목이 달라진
초안은 최신 공식 데이터를 덮어쓰는 데 사용하지 않는다. 성공하면 초안을 제거한다.
공식 저장 실패 시 편집값과 마지막 유효 계산을 유지하고 재시도를 제공한다.
브라우저가 복구 초안 저장까지 거부하면 메모리 편집만 보존할 수 있으므로 페이지
이탈 경고를 유지한다. 탭 간 localStorage 충돌 검사는 최선의 감지이며 원자적 트랜잭션은 아니다.

## 1. 합성 정규화 — `composite.ts`

```
z_std = Σwᵢzᵢ / √(Σwᵢ² + 2Σᵢ<ⱼ wᵢwⱼρᵢⱼ)
```

**왜 분모가 필요한가.** `Σwᵢzᵢ`의 분산은 1이 아니다. 4요소 균등가중(w=0.25)·독립이면
`Σwᵢ² = 0.25`, 즉 표준편차가 **0.5**다. 이 값을 표준정규로 읽는 것은 반올림 오차가 아니라
**체계적 편향**이다. 테스트가 이 배율을 못 박아 둔다 — 같은 입력에서 순진한 버전은 1.0,
정규화 버전은 2.0을 낸다 (정확히 2배).

**ρ를 숨기지 않는다.** 평가요소 간 상관은 대략 0.5~0.7이다(중간 잘 본 사람이 기말도 잘 본다).
ρ=0으로 놓으면 σ_S를 과소추정해 앱이 근거 없이 낙관적인 답을 준다. 그렇다고 ρ를 하나 골라 쓰면
그 선택 자체가 false precision이다. → **ρ=0.3 / ρ=0.8 두 경우를 모두 계산해 구간(`zRange`)으로**
출력하고, 확률분포는 두 경우의 **균등 혼합**으로 낸다.
몬테카를로는 쓰지 않는다(회의록 4-5 스코프 절단선). 해석해로 충분하다.

**등상관을 쓰는 이유 — 공짜로 얻는 것.** 모든 쌍에 같은 ρ를 가정하면 1-요인 모형
`Zᵢ = √ρ·F + √(1−ρ)·Eᵢ` 와 동치가 된다. 덕분에 **아직 안 본 시험**의 조건부 분포가 닫힌 형태로 나온다.

```
F | z_A ~ N( √ρ·Σz / (1−ρ+n_A·ρ),  (1−ρ)/(1−ρ+n_A·ρ) )
```

즉 "중간 잘 봤으니 기말도 그 정도 하겠지"를 **가정이 아니라 모형에서 유도**하고,
남은 시험의 불확실성이 `tau`로 자동으로 구간에 반영된다.

**유효 가중치.** 회의록 수식은 명목 반영비율 wᵢ를 쓰지만, 그것은 요소별 σ가 같다는 가정 위에서만
원점수 합성과 일치한다. 엔진은 `wᵢ_eff ∝ wᵢ·σ̃ᵢ` (σ̃ᵢ = stdevᵢ/maxᵢ)를 쓴다.
σ가 모두 같으면 `wᵢ_eff = wᵢ`가 되어 **회의록 수식 그대로로 환원**된다.

## 2. 천장 밀집 요소 분리 — `ceiling.ts`

출석·과제는 대부분 만점이라 분포가 극단적으로 찌그러져 있다. z-score를 적용하면
만점 못 받은 사람의 z가 −3처럼 튀어, 반영비율 20%짜리 출석 한 번 빠진 것이
기말을 20점 망친 것처럼 계산된다.

**대응은 "제외"가 아니라 "경로 분리"다.** 두 가지를 구분해야 한다.

- **분산 기여 = 0.** `ceilingClustered` 요소는 z 경로에 아예 들어가지 않는다.
  구간의 폭(`tau`)에 한 톨도 기여하지 않는다.
- **위치 이동 ≠ 0.** 출석에서 2점을 잃으면 총 환산점수가 반 평균보다 2점 낮아지고
  그만큼 등수가 밀린다. 이것은 확률변수가 아니라 **결정론적 평행이동**이므로,
  환산점수 편차를 아래 계수로 환산해 합성 z를 평행이동만 시킨다.

```
Δz_std = Δ환산점수 / (100 · T · D)      T = Σwⱼσ̃ⱼ,  D = √(Σwᵢ²+2Σwᵢwⱼρ)
```

유도: 요소 i에서 Δs점을 더 받으면 환산점수는 `wᵢ·Δs·100/maxᵢ`, zᵢ는 `Δs/stdevᵢ` 만큼 움직인다.
`wᵢ_eff = wᵢσ̃ᵢ/T` 를 대입하면 **요소와 무관하게 계수가 같다**. 이 성질이
"어디에 1점을 넣는 게 가장 남는가"를 과목 간에 비교 가능하게 만든다(§7).

> 이 평행이동이 없으면 "결석해도 예상 등급이 꿈쩍 않는" 엔진이 되어
> 앱의 질문("째도 되나") 자체에 답하지 못한다. 초기 구현에서 실제로 발생한 버그이고,
> 테스트 `천장 밀집 요소는 z경로가 아니라 결정론적 평행이동으로만 예측을 움직인다`가 지킨다.
>
> **회의록 문구("z경로에서 제외")를 넘어서는 해석 확장이며, 조율자 승인을 받았다
> (CONTRACT.md 7-3).** 발표에서는 "회의록을 그대로 구현했더니 핵심 질문에 답을 못 해서
> 한 겹 더 분해했다"는 서사로 쓸 수 있다.

**자동 감지.** 평균이 만점의 80% 이상이면 `CEILING_EFFECT`. 플래그가 안 붙은 요소가 걸리면
그 사실을 문구에 담는다(변별 요소인 줄 알았는데 실은 천장 밀집인 경우가 더 중요한 신호다).
경고는 등급 단정 대신 **"1~2점 차이로 등급이 갈릴 수 있음"** 으로 간다.
역설적으로 상위권에게 더 쓸모 있고, 행동을 바꾸는 쪽은 이쪽이다.

## 3. 정규 → 베타 전환 — `beta.ts`

점수는 0~100에 갇힌 유계 변수다. 0~1로 정규화하면 Beta(α, β)로 모델링된다.

```
α = mκ,  β = (1−m)κ,  κ = α+β (집중도)
분산 = m(1−m) / (κ+1)      ⇒  κ = m(1−m)/s² − 1
```

**치환의 이득은 실재한다.** "σ를 모른다"가 "κ 하나를 모른다"로 바뀐다.

- 정규 가정에서 σ는 자유 파라미터라 평균이 50이든 85든 같은 범위를 갖다 붙인다.
- 베타에서는 **같은 κ 범위라도 m에 따라 σ 범위가 자동으로 달라진다.**
- "평균이 극단이면 σ가 작을 수밖에 없다"가 가정이 아니라 **모델에 내장**된다.

### 3.1 상위권 왜곡 — 측정된 수치

평균 85 · σ 12인 시험에서 정규 가정은 **100점 초과에 10.6%** 의 확률질량을 둔다.
존재할 수 없는 사람들이 상위권을 밀어내는 것이 왜곡의 실제 기전이다.
왜곡은 **천장 바로 아래에서 가장 크다**:

| 원점수 | 정규: 내 위에 | 베타: 내 위에 | z(정규) | z(베타) |
|---:|---:|---:|---:|---:|
| 90 | 33.9% | 42.7% | 0.42 | 0.18 |
| 95 | 20.2% | 22.0% | 0.83 | 0.77 |
| **99** | **12.2%** | **3.7%** | **1.17** | **1.78** |

99점을 받고도 정규 가정은 "내 위에 12%"라고 말한다. 그 12% 중 대부분은 100점을 넘는,
**존재할 수 없는 점수**다. 베타는 3.7%라고 말한다. `A 정원 12명`인 40명 수업에서
이 차이는 등급을 바꾼다.

> **★발표 시 주의 — 표현을 "천장 직전에서만 크게 뒤집힌다"로 통일할 것.**
> 회의록은 100점 초과 질량을 "상위권 백분위 왜곡의 주범"이라고만 적고
> **교정의 방향이 점수대마다 반대라는 점을 짚지 않았다.** 위 표대로 90·95점에서는
> 베타가 오히려 더 박하고, 뒤집히는 것은 천장 직전뿐이다.
> "상위권이면 다 올라간다"고 말하면서 95점 사례를 들면 주장과 반대 결과가 나온다.
> **반드시 99점 사례를 쓸 것.**
> (이 표는 조율자가 파이썬 수치적분으로 독립 재현해 소수점까지 일치 확인했다.
>  κ=7.854, α=6.676, β=1.178, 정규의 만점 초과 질량 10.6%. CONTRACT.md 7-2에도 기록됨.)

### 3.2 2층 판정 — 두 제약은 다른 층이다

회의록의 *"평균 85점 시험에서 σ가 25일 수 없다"* 는 실제로는 분산 상한에 걸리지 않는다.

- **1층 — 분산 상한** `s² ≥ m(1−m)`: 베타로 표현 자체가 불가능. **거부**한다.
  m=0.85의 분산 상한은 0.1275 → **σ 상한은 약 35.7점**이므로 σ=25는 여기를 통과한다.
- **2층 — 형태 타당성** `α = mκ < 1` 또는 `β = (1−m)κ < 1`: 베타가 U자형(양 끝 밀집)이 된다.
  수학적으로는 합법이지만 시험 점수 분포로는 비현실적이다.
  **σ=25@평균85가 실제로 걸리는 곳이 여기다 (κ ≈ 1.04).**

2층은 거부하지 않고 **표시만** 한다. 수강포기자 다수처럼 진짜 이봉분포인 시험이 존재하기 때문이다.
엔진은 이때 정규 근사로 폴백하고 그 사실을 경고로 남긴다.
(`lib/backtest/kappa.ts`의 `estimateKappa`와 동일한 규약 — 조율자 구현과 교차 검증됨.)

### 3.3 κ 프리셋 — ★잠정값★

사용자는 무차원 값 κ를 직접 못 고르므로 **체감난이도 라벨**에 매핑한다.

| 라벨 | κ 범위 |
|---|---|
| 쉬움 | 12.9 ~ 16.3 |
| 보통 | 8.9 ~ 12.9 |
| 어려움 | 5.9 ~ 8.9 |
| 매우 어려움 | 5.5 ~ 5.9 |

출처는 조율자의 `buildKappaReport`가 **합성 샘플**에서 역추정한 사분위(Q1=5.9 / 중앙=8.9 / Q3=12.9)다.
**실제 성적 데이터가 아니므로 "근거 있는 프리셋"이라고 말하면 안 된다.** UI에 "잠정"을 노출할 것.

개념적 한계도 같이 적어 둔다: κ는 "집중도"이고 체감난이도는 주로 평균 m에 실린다.
**난이도 → κ 매핑 자체가 하나의 가정**이며, 데이터로 확인된 것은 κ의 분포 범위일 뿐
난이도와의 대응관계가 아니다.

### 3.4 한계 — 과장 금지

천장효과는 **"해결"이 아니라 "완화"** 다. 베타는 연속분포라 *만점자 8명* 같은 동점 밀집을
표현하지 못한다. 만점자에게는 연속성 보정(만점자 집단의 중앙)으로 유한한 z를 주지만, 근사다.

## 4. 정밀도 사다리 — `tier.ts`

없는 정보를 가정으로 메우는 대신, 가진 정보의 양에 따라 **출력의 종류 자체**를 바꾼다.

| Tier | 가진 것 | 내는 것 |
|---|---|---|
| 0 | 아무것도 없음 | 절대점수 계산기로 격하. **등급을 언급하지 않는다** (`distribution = null`) |
| 1 | 평균만 | **blur.** `distribution = null` + `LOW_TIER` + "표준편차를 넣으면 등급이 보입니다" |
| 2 | 평균 + 친구 점수 | **구현하지 않음** |
| 3 | 평균 + 표준편차 | 정석 경로. 구간 + 누적 확률분포 |
| 4 | 등수 공개 | 계산 불필요. 백분위 직행 |

**Tier 4 진입 경로는 둘이다.** ①`Course.myRank` + `Course.enrolled` (기본, 사용자 입력)
②`PredictOptions.rank` (외부 주입 — 백테스트가 `BacktestCase.actualRank`를 넣는 경로). 둘 다 있으면 ②가 이긴다.
등수만 있고 수강인원이 없거나 등수가 인원을 넘으면 백분위를 못 내므로 **조용히 일반 경로로 내려간다** — 등급을 지어내지 않는다.

**Tier 1에서 σ를 12~18로 가정해 구간을 내면 안 되는 이유.** 그 구간의 폭은 데이터가 아니라
우리 가정에서 나온 것이다. 사용자는 그것을 "데이터 기반 불확실성"으로 읽지만 실제로는
"모른다"를 숫자로 위장한 것 — **정직해 보이는 형식으로 포장된 false precision**이 제일 나쁘다.
blur가 더 정직하고, 추가 입력 동기도 된다.

**Tier 2를 뺀 이유** (회의록 4-5 [잘라낼 것]). 백테스트로 실제 축소폭을 확인한 뒤 결정하기로 보류됐다.
self-selection 편향(점수 낮으면 안 알려줌 → 상방 편향)이 미처리이고, n=3~5의 표본 불확실성 때문에
"±1.2등급 → ±0.5등급" 약속만큼 안 좁아질 수 있다. **약속한 만큼 안 좁아지면 아예 안 좁아진 것보다
신뢰 손상이 크다.** 테스트가 `resolveTier`가 절대 2를 내지 않음을 못 박는다.

**τ 하한 (`TAU_FLOOR`).** 미응시 요소의 불확실성과 별개로 모형 자체의 오차가 있다
(ρ 미지, 정원 비율 가정, κ/σ 추정오차, 등상관 가정). 0으로 두면 시험이 다 끝난 과목에서
확률이 0%/100%로 붙어 버린다. 현재 T3=0.15 / T4=0.05.

**이 값은 근거가 없고, 그래서 지금은 고정한다** (조율자 결정). 합성 샘플 9건에 맞춰 튜닝하면
그것이야말로 우리가 내내 반대해 온 "숫자로 위장한 추측"이고, 생성기가 엔진과 같은 상관구조를
쓰므로 거기 맞춘 값은 실제 데이터에서 의미가 없다. 실제 팀원 성적이 들어올 때까지 유지한다.

대신 **민감도를 재는 구멍**을 열어 뒀다 — §10 참조. "근거는 없지만 결과가 거의 안 흔들린다"를
보일 수 있으면 약점이 방어 논거가 된다.

## 5. 학점 잔고 — `balance.ts`

환산점수(0~100) 척도에서 ①확보 `secured` ②상실 `lost` ③잔여 `remaining`.

```
기여분 = 반영비율 × (내점수/만점) × 100
감점분 = 반영비율 × ((만점−내점수)/만점) × 100
유효 결석 = 결석 + 지각/latePerAbsence
```

**이중 차감 방지.** 출결 장부와 "출석" 평가요소가 둘 다 있으면 같은 결석을 두 번 깎게 된다.
규칙: **천장 밀집 요소에 점수가 직접 입력돼 있으면 장부 감점을 적용하지 않는다**
(사용자가 넣은 점수가 더 확정적인 정보다). 어느 쪽을 썼는지는 경고로 밝힌다 — 침묵하면
사용자는 결석이 반영된 줄 안다.
단, what-if의 "한 번 더 결석"은 **한계 손실**이므로 이 경우 입력된 출석 점수 쪽에서 직접 깎는다.

**구조적 이점** (회의록 4-1, 발표 논거). 출결 트래커 단독은 "기본값=출석"이라 결석 입력을
잊으면 잔고를 **위험한 방향으로** 과대 표시한다. 그런데 "째도 되나"를 조회하려면 잔고가
최신이어야 하므로, **조회 니즈가 입력을 견인해** 이 결함이 자동 해소된다.
출결 트래커 단독으로는 못 얻던 성질이다.

## 6. 비교 예측 — `whatif.ts`

> (약함) "당신은 A0입니다" ← 틀리면 신뢰가 무너진다
> (강함) "이번 주 결석하면 A0 이상일 확률이 눈에 띄게 줄어듭니다"

같은 가정 하의 두 시나리오 **차분**은 공통 편향이 상쇄되어 수준 추정보다 robust하다.
σ를 잘못 잡았어도, ρ를 잘못 잡았어도, 정원 비율을 잘못 잡았어도 두 시나리오에 똑같이
들어가므로 차이에서는 상당 부분 지워진다.

**기준선을 따로 만든다.** "기말 +5점"에서 아직 안 본 시험을 그냥 "평균+5점"으로 채우면
*+5점의 효과*에 *불확실성이 사라진 효과*가 섞여 차분이 부풀려진다. 그래서 기준선도
같은 방식(`E[Zⱼ|z_A]`, §1)으로 채운 뒤 두 쪽을 비교한다.

**★단서를 반드시 단다.** 등급은 컷오프가 있는 **비선형 변환**이라 경계선 근처에서는 차분도
불안정하다. "공통 편향 상쇄로 덜 틀림"을 무조건 주장하지 않는다. `borderlineFlag`가
**모델 한계의 고백 장치**이며, ①어느 쪽이든 `BORDERLINE`이거나 ②시나리오가 50% 선을
넘나들면 선다. 확률 변화는 숫자 없이 4단계 언어로만 표현한다
(거의 그대로 / 조금 / 눈에 띄게 / 크게).

## 7. 변별 기여도 — `discrimination.ts` (킬러 기능)

분산 분해. `vᵢ = wᵢσᵢ` 로 두면

```
σ_S² = Σvᵢ² + 2Σᵢ<ⱼ vᵢvⱼρ
기여도ᵢ = (vᵢ² + ρ·vᵢ·Σⱼ≠ᵢ vⱼ) / σ_S²        (공분산항을 두 요소에 절반씩 배분 → 합 = 1)
```

**드러나는 사실: 반영비율과 실제 등급 영향력은 전혀 다르다.** 출석이 20%여도 다들 만점이면
등급에 미치는 실질 영향은 0에 수렴한다. "출석만 잘 하면 되겠지"라는 흔한 오해를 정면으로 깨고,
시험 **전에** 유효해서 조회 시점과 행동 가능 시점이 일치한다.
(단, 이 주장을 어느 방향으로 해야 방어되는지는 §7.1을 반드시 볼 것.)

**★구조적 모순과 그 대응.** 이 계산에는 요소별 σᵢ가 필요한데, σ를 모르는 것이 이 앱의 최대 난점이다.
그래서 **절대 숫자를 반환하지 않는다.** `ImpactBand` 3구간만 낸다.
"62%"를 내보내는 순간 공들여 막아온 false precision이 **킬러 기능이라는 뒷문**으로 재진입하고,
"확신을 못 주는 게 옳다"는 앱 전체의 일관성도 깨진다.
`DiscriminationContribution`에 수치 필드가 없다는 것을 테스트가 필드 단위로 검사한다.
ρ=0.3/0.8 양쪽에서 계산해 **더 보수적인(낮은) 밴드**를 채택한다.
밴드 경계(`DEFAULT_IMPACT_BANDS`: negligible<0.10, decisive≥0.40) 역시 근거 없는 상수라
τ 하한과 같은 이유로 고정하고, 민감도 측정용 오버라이드만 열어 뒀다(§10).

**부분 구제.** 출석·과제가 "다들 만점"이라는 사실 자체가 **σ≈0이라는 정보**다.
σ를 하나도 몰라도 "출석·과제는 등급을 거의 가르지 않는다"는 **방향성은 낼 수 있다.**

### 7.1 ★발표에서 주장할 수 있는 것과 없는 것 (민감도 스윕 결과)

조율자가 밴드 경계를 훑어 본 결과(56개 평가요소, CONTRACT.md 7-4):

| 컷 (negligible / decisive) | negligible | supporting | decisive |
|---|---:|---:|---:|
| 0.05 / 0.30 | 23 | 17 | 16 |
| **0.10 / 0.40 (동결값)** | **28** | **17** | **11** |
| 0.15 / 0.50 | 28 | 22 | 6 |
| 0.20 / 0.60 | 28 | 28 | **0** |

- `negligible` 판정은 컷을 바꿔도 거의 안 움직인다 (변동 **5/56**).
- `decisive` 판정은 컷에 크게 의존한다 (변동 **16/56**). 0.20/0.60으로만 옮겨도 **0건**이 된다.

| | |
|---|---|
| ❌ **주장 금지** | "기말이 사실상 등급을 결정한다" |
| ✅ **주장 가능** | "출석·과제는 등급을 거의 가르지 않는다" |

`decisive`는 근거 없는 컷(0.40)에 얹혀 있어서, 질의응답에서 *"그 0.40은 어디서 나왔나요"* 가
들어오면 방어가 안 된다. 반면 `negligible`은 컷에 거의 무관하고, 근거도 컷이 아니라
**"다들 만점이라는 사실 자체가 σ≈0"** 이라는 위의 부분 구제 논리다.

역설적이지만 이쪽이 **더 강한 주장**이다. 회의록 4-4가 말한 킬러 기능의 가치는
*"출석만 잘 하면 되겠지"라는 오해를 깨는 것*이었고, 그건 애초에 `negligible` 쪽 판정이지
`decisive` 쪽이 아니었다.

> 엔진 코드는 바꾸지 않았다. `decisive` 밴드 자체는 계속 계산되고 화면에도 나간다 —
> 한 과목 안에서 어디에 힘을 쏟을지 고르는 데는 여전히 유용하다.
> 제약은 **발표에서 그것을 일반화된 사실로 단정하지 말라**는 것이다.

## 8. 배분 대시보드 — `allocation.ts`

과목을 **확정권 `locked` / 경계권 `borderline` / 역전권 `reversible`** 로 나누고,
**"기말 +1점당 예상 학기평점 상승폭"** `gpaGainPerPoint` 으로 정렬한다.
§2의 `Δz_std = 1/(100·T·D)` 가 요소와 무관한 계수이므로 과목 간 비교가 성립한다.

```
gpaGainPerPoint = (E[GPA | z+Δz] − E[GPA | z]) × 학점 / 총학점
```

**★시간 환산은 의도적으로 하지 않는다.** "1시간 투자 → 몇 점"은 개인차·과목차가 커서
앱이 알 수 없다. 모르는 것을 곱하면 뒤의 모든 숫자가 오염된다.
**"어디에 1점을 넣는 게 가장 남는가"까지가 앱이 정직하게 말할 수 있는 한계다.**
`AllocationRow`에 시간 관련 필드가 없다는 것을 테스트가 검사한다.

재방문 논리의 핵심이기도 하다 — 조회가 아니라 **시뮬레이션**이라 반복적이다.

## 9. 출력 규칙과 예측 제외

**누적확률로만** 낸다. "A0 55%"가 아니라 **"A0 이상일 확률 70%"**.
사람은 최빈값 하나만 읽고 "나 A0구나"로 축약하는 경향이 있기 때문이다.

**백분위 대신 인원수로**: "상위 11%"보다 `40명 중 A 정원 12명, 내 위로 추정 8명`.

**예측하지 않는 경우** — 모두 `distribution = null` 로 격하한다.

| 조건 | 경고 |
|---|---|
| 수강인원 20명 이하 | `SMALL_CLASS` |
| 절대평가 | `ABSOLUTE_GRADING` |
| 결석 한도 초과 | `ATTENDANCE_RISK` (F 여부가 등급 확률보다 먼저다) |
| 평균 없음 / 표준편차 없음 | `LOW_TIER` |

**정원 비율은 가정이다.** 기본값 A 30% / B 40% / C 20% / D 10% (회의록 예시 "40명 중 A 12명"에 맞춤).
학교·학과·교수마다 다르고 공개된 단일 기준이 없다. `DEFAULT_QUOTA`로 교체 가능하며 UI에서 가정임을 밝힐 것.

## 10. 근거 없는 상수와 민감도 훅

엔진에는 데이터로 뒷받침되지 않는 상수가 셋 있다. **숨기지 않고 여기 모아 둔다.**

| 상수 | 현재 값 | 성격 |
|---|---|---|
| `TAU_FLOOR` | T3=0.15 / T4=0.05 | 모형 자체 오차의 하한 |
| `DEFAULT_QUOTA` | A30 / B40 / C20 / D10 | 상대평가 정원 비율 |
| `DEFAULT_IMPACT_BANDS` | negligible<0.10, decisive≥0.40 | 변별 기여도 밴드 경계 |

**합성 샘플에 맞춰 튜닝하지 않는다.** n=9에 맞춘 값은 "숫자로 위장한 추측"이고,
생성기가 엔진과 같은 상관구조(ρ=0.6)를 쓰므로 실제 데이터에서 의미가 없다.
캘리브레이션 중간 구간도 n=2/3/1이라 읽을 수 있는 신호가 아니다.

**대신 흔들림을 잰다.** 값을 훑으며 적중률·구간포함률·Brier가 얼마나 움직이는지 보면,
"근거는 없지만 결과가 거의 안 흔들린다"를 보일 수 있고 약점이 방어 논거가 된다.
조율자가 `npm run sensitivity` 로 스윕을 붙였고, 결과는 아래 10.1 / §7.1에 있다.
**스윕 범위를 좁게 잡으면 결론이 뒤집힌다** — 10.1이 실례다.

```ts
predict(course, { tauFloor: { t3: 0.05 } });          // τ 하한 스윕
predict(course, { quota: myQuota });                   // 정원 비율 교체
contributions(course, { bands: { negligible: 0.05, decisive: 0.5 } });  // 밴드 경계 스윕
```

전부 optional이라 **미지정 시 기본값과 완전히 동일한 결과**를 낸다(테스트가 검사).
`bands`의 두 값이 뒤집혀 들어와도 정렬해서 받으므로 밴드 구조가 무너지지 않는다.
평상시 호출에서는 지정하지 않는다 — 이 구멍은 측정용이지 튜닝용이 아니다.
`allocate()`도 같은 `PredictOptions`를 받고 `PredictionInternals.tauFloor`를 통해
`predict()`와 **같은 τ를 공유**한다. 이게 없으면 스윕에서 "적중률은 그대로인데 배분 순위만
움직이는" 설명 불가능한 결과가 나온다.

### 10.1 τ 하한 스윕 결과 (합성 샘플 n=9)

`npm run sensitivity` 가 15점 격자로 돌며 고원 경계를 자동 탐색한다.
아래는 경계를 추가로 좁힌 값이다.

| τ | 적중률 | 구간포함 | Brier | |
|---:|---:|---:|---:|---|
| 0.0001 | 77.8% | 77.8% | 0.5556 | |
| 0.0135 | 77.8% | 77.8% | 0.4749 | |
| **0.0136** | 77.8% | **88.9%** | 0.4746 | ← 고원 **시작** |
| 0.03 | 77.8% | 88.9% | **0.4575** | ← Brier 극소 |
| **0.15** | **77.8%** | **88.9%** | **0.4943** | **동결값** |
| 0.30 | 77.8% | 88.9% | 0.5715 | |
| **0.3800** | 77.8% | 88.9% | 0.6046 | ← 고원 **끝** |
| 0.3801 | **66.7%** | 88.9% | 0.6046 | |
| 0.5314 | 66.7% | **100.0%** | 0.6487 | |

**고원 = 0.0136 ≤ τ ≤ 0.3800.** 이 안에서 적중률·구간포함률이 **전혀 안 움직인다**(변동 0.0%p).
확률은 50%쪽으로 수축하지만(§4의 성질) 최빈 등급과 80% 구간의 **경계를 넘지 않기** 때문이다.

**고원에는 양쪽 가장자리가 있다.**
- 아래쪽 **0.0135 / 0.0136 사이** — 구간이 너무 좁아져 구간포함률이 88.9%→77.8%로 떨어진다.
- 위쪽 **0.3800 / 0.3801 사이** — 분포가 평평해져 최빈 등급이 정원 최대 버킷으로 끌려가고
  적중률이 77.8%→66.7%로 떨어진다.

**두 지표는 동시에 무너지지 않고 순차적으로 무너진다.** 이것이 "고원 밖에서는 변한다"를
구체적으로 만드는 부분이다.

```
τ ≤ 0.0135  구간포함 77.8%   구간이 좁아 실제 등급을 놓침
0.0136 ~ 0.3800   ← 고원. 적중 77.8% / 구간포함 88.9% 고정
τ ≥ 0.3801  적중   66.7%   최빈 등급이 정원 최대 버킷으로 끌림
τ ≥ 0.5314  구간포함 100%   구간이 넓어 아무거나 포함 (적중률 붕괴와 다른 지점)
```

마지막 줄의 100%는 "잘 맞혔다"가 아니라 구간이 무의미해졌다는 뜻이다. 적중률 붕괴(0.3801)와
**0.15 이상 떨어진 별개의 지점**이라는 것이 중요하다.
(세 경계 모두 `npm run sensitivity` 의 이분 탐색이 자동으로 뱉는다 — 안쪽/바깥쪽을 쌍으로
 들고 방향성 반올림을 하므로 고원 폭이 과대보고되지 않는다.)

동결값 0.15는 고원 안에 있다 (선형 37% 지점, 로그 72% 지점 — 어느 척도로 봐도 가장자리는 아니다).

> 경계값의 유효자릿수는 통계적 정밀도가 아니다. 이 경계는 **9건 중 특정 1건의 구간/최빈값이
> 뒤집히는 이산적 사건**이라 위치 자체는 날카롭게 정의되지만, 그 위치는 **이 9건에 고유하다.**
> 실데이터에서는 완전히 다른 값이 나온다. 발표에서는 자릿수가 아니라 **"고원이 존재하고
> 동결값이 그 안에 있다"** 를 말할 것.

**★Brier는 단조가 아니라 U자다.** 0.03 부근에 극소가 있고 양쪽으로 올라간다.
0.05~0.30 만 보면 오른쪽 가지만 보여 단조 증가처럼 보인다.
**판정 근거가 스윕 범위에 의존하면 범위를 바꾸는 순간 결론이 뒤집힌다** — 실제로 한 번 뒤집혔다.
그래서 판정 로직은 단조/극소 기준을 버리고 **고원 탐색 기준**으로 바뀌었고,
Brier 극소는 위치만 보고하고 최적값으로 채택하지 않는다.

- ✅ **주장 가능**: "**τ 0.014~0.38 전 구간에서** 등급 결론이 같고, 동결값은 그 고원의 한복판이다.
  고원 밖에서는 변하며, 그 경계도 측정했다."
- ❌ **주장 금지**: "τ 값과 무관하다" (0.385에서 깨진다) / "최적값을 찾았다".
- ⚠ **Brier 극소 0.03을 동결값 후보로 쓰지 말 것.** 두 가지 이유이고, 둘 다 범위와 무관하다.
  ① n=9에서 0.4575 vs 0.4943 은 노이즈 수준이다.
  ② 생성기가 엔진과 같은 ρ=0.6을 써서 **모형오차가 구조적으로 0**이다.
     모형오차 하한을 모형오차가 없는 데이터로 고르는 것은 순환논증이다.
  **이 데이터로는 τ를 고를 수 없다.**

**실데이터가 들어오면 0.0001~1.0 전 구간으로 재스윕할 것.** 관전 포인트는 **고원 가장자리의 이동**이다.
합성 데이터는 모형오차가 0이라 고원이 실제보다 **넓게** 나왔을 가능성이 크다.
실데이터에서 고원이 좁아지면 **0.15가 더 이상 한복판이 아닐 수 있고**, 그러면 동결값을 옮겨야 한다.

## 13. 성적 관리 v2 — 진행 상태와 4영역 잔고

기존 `Course`, `Assessment`, `GradeBalance`, 확률 엔진과 v1 저장 API는 변경하지 않는다.
새 관리 API는 아래 파일에서 직접 가져온다. 학점 UI는 v2를 사용하며,
v1은 명시적 이전 검토를 거친다. 자동 마이그레이션·양방향 동기화·출석 규칙 개편은 하지 않는다.

| 파일 | 공개 API / 역할 |
|---|---|
| `management-types.ts` | `AssessmentProgress`, `ManagedAssessment`, `ManagedCourse`, `FourAreaBalance`, `ManagedBalance`, `ManagementResult` |
| `management.ts` | `validateManagedCourse(s)`, `migrateV1Courses`, `transitionAssessment`, `toEngineCourse` |
| `managed-balance.ts` | `computeManagedBalance` — 실제 기록만으로 계산하는 순수 함수 |
| `managed-storage.ts` | `loadManagedCourses`, `saveManagedCourses`, `prepareV1Migration`, `saveV1Migration` |
| `__tests__/managed-model.test.ts` | 상태 전환, 배점 보존, 엔진 호환성, 안전한 변환·저장 실패·복원 검증 |

각 함수는 성공 시 `{ ok: true, value }`, 실패 시 `{ ok: false, errors }`를 반환한다.
진행 상태는 `scheduled`, `awaiting_grade`, `graded(score)`,
`zero_confirmed(reason: absent | not_submitted)` 네 종류다.
`graded(0)`은 정상적으로 입력된 실제 0점으로 보존하며 미응시 사유를 추정하지 않는다.
`transitionAssessment`는 명시적 정정으로 모든 상태 간 이동을 허용하고 원본을 바꾸지 않는다.
예정·채점 대기 상태로 돌아가면 이전 점수·사유가 새 상태에 남지 않는다.

반영비율 `w`, 만점 `M`, 확정 점수 `s`에 대해 환산 배점은 `P=100w`이다.

| 상태 | 확보 | 상실 | 미확정 | 남은 배점 |
|---|---:|---:|---:|---:|
| 예정 | 0 | 0 | 0 | P |
| 채점 대기 | 0 | 0 | P | 0 |
| 점수 확정 | P·s/M | P−P·s/M | 0 | 0 |
| 미응시·미제출 0점 확정 | 0 | P | 0 | 0 |

비율은 0~1이고 합계 1을 검증한다(기존 v1과 동일한 부동소수점 오차 허용).
합계가 잘못되면 계산·저장을 거부하며 자동 정규화하지 않는다.
계산 도중 반올림하지 않으므로 화면 표시에서만 반올림해야 한다.

v1의 `myScore=null`은 예정인지 채점 대기인지 알 수 없다.
따라서 `progress=null`, `reviewRequired='legacy_null_score'`로 보존한다.
이는 평가 진행 상태가 아니라 변환 후 확인할 데이터다.
그 배점은 네 영역 중 어느 곳에도 추정 배정하지 않고
`review.unclassifiedPoints`와 `review.assessmentIds`로 알린다.
`네 영역 합 + unclassifiedPoints = totalPoints`가 성립하며 `complete=false`이다.
진행 상태가 모두 확인되고 별도 출결 장부가 없으면 네 영역의 합은 100점이고 `complete=true`이다.
기존 출결 장부는 복사·보존하되 이 계산기에서 별도 감점하지 않고
`review.attendanceLedgerPreserved=true`, `complete=false`로 개편 전 검토 필요를 표시한다.
따라서 이 계산 결과를 출결 장부까지 반영된 최종 성적으로 단정하면 안 된다.

`toEngineCourse`는 예정·채점 대기를 `myScore=null`, 확정 점수를 실제 값,
미응시·미제출 확정을 0으로 변환한다. 상태 확인이 남아 있으면 연결을 거부한다.
기존 엔진의 `remaining`은 미확정과 예정 배점을 합친 의미이므로
새 4영역 잔고 대신 사용하지 않는다. 확률·조건부 추정은 기존 엔진의 역할이며,
실제 점수로 저장하거나 `secured`에 포함하지 않는다.

저장 키는 v1 `erica.grade.courses.v1`, v2 `erica.grade.courses.v2`로 분리한다.
v2 문서 형식은 `{ version: 2, courses: ManagedCourse[] }`다.
`prepareV1Migration()`은 읽기 전용 미리보기를 반환한다.
호출자가 검토 후 `saveV1Migration(preview)`를 호출해야 v2가 저장된다.
저장 직전 v1 원본 스냅샷과 v2 부재를 다시 확인하며, v1 키에는 쓰거나 삭제하지 않는다.
기존 v2가 있거나 손상된 경우 v1으로 덮어쓰지 않는다.
일반 v2 수정은 `saveManagedCourses(courses, expectedSnapshot)`으로 충돌을 확인한다.
localStorage 비교·쓰기는 탭 간 원자적 트랜잭션이 아니라 최선의 충돌 감지다.
저장 실패는 오류로 반환하고 호출자의 편집 데이터는 바꾸지 않는다.
이전 v1 클라이언트에서 수정한 데이터가 v2로 자동 반영되지는 않는다.
v2가 있으면 비어 있어도 v1을 다시 합치지 않는다.

## 14. 과제 세부 관리

`ManagedAssessment.assignmentGroup`은 선택 필드다. 기존 v1·v2의 단일 과제는
변환하거나 자동 분할하지 않는다. 그룹의 전체 비율은 부모 `weight`이고,
각 `AssignmentTask.weight`는 그룹 내부 비율이다. 과제 수는 `tasks.length`에서만 얻는다.
그룹이 활성화되면 부모 `progress`는 복원용 기록으로 보관하고 계산에 중복 반영하지 않는다.

`allocation`은 `unconfirmed` / `equal` / `individual`이다.
`equal`은 사용자가 직접 선택해야 하며 내부 비율을 `1/tasks.length`로 계산한다.
`individual`은 내부 비율 합계 1을 검증하고 자동 보정하지 않는다.
`unconfirmed`는 실제 점수·진행 기록을 저장할 수 있지만 전체 그룹 배점을
`review.unclassifiedPoints`로 남기고 네 영역에 임의 분배하지 않는다.

`assignments.ts`는 그룹 검증, 개별 상태 전환, `computeAssignmentBalance`,
`assignmentAggregateScore`, `assignmentChangeMessages`를 제공한다.
기존 항목과 세부 과제는 `assessment-progress.ts`의 동일한 실제 배점 계산을 사용한다.

예: 전체 20%, 균등한 과제 5개, 첫 과제 80/100, 둘째 채점 대기, 나머지 예정이면
그룹의 확보 3.2 / 상실 0.8 / 미확정 4 / 남은 배점 12점이다.
계산 중 반올림하지 않고 화면 표시에서만 반올림한다.

세부 과제 일부만 확정되면 4영역은 계산하지만 `toEngineCourse`는 등급 예측을 보류한다.
배점이 확인되고 모든 과제가 점수 확정 또는 미제출 0점 확정일 때만
`부모 만점 × Σ(내부 비율 × 개별 득점률)`로 정확한 그룹 점수를 만든다.
그룹 평균·표준편차를 그대로 유지한 **부모 평가항목 1개**만 기존 엔진에 전달한다.
세부 과제를 독립적인 확률 입력으로 펼치거나 그룹 통계를 새로 추정하지 않는다.

기존 v2 저장 문서에 선택 필드를 추가하므로 키와 버전은 유지한다.
`saveManagedCourses(courses, snapshot, access?, confirmedAssignmentChanges?)`는
저장된 문서와 새 문서에서 실제 과제 변경 내역을 계산한다.
그룹 전환·제거, 과제 삭제, 배점 재분배, 확정 점수·만점 변경은
명시적 확인 인수가 없으면 저장을 거부한다. UI는 전후 기록과 배점을 보여주고 확인받는다.
단순 예정→채점 대기, 신규 점수 입력, 이름 수정은 파괴적인 변경 확인을 요구하지 않는다.
편집·계산·미리보기는 원본을 바꾸지 않으며 저장 실패 시 편집 중인 기록을 유지한다.

`__tests__/assignments.test.ts`는 상태 전환, 균등/개별 배점, 미확인 배점,
중복 합산 방지, 그룹 단위 엔진 연결, 변경 확인, 기존 데이터·저장 실패 호환성을 검증한다.

## 15. 이전 데이터 호환 참고 — 기록 기반 출석 관리

공유 `AttendanceLedger`와 기존 확률 수학 모델은 수정하지 않는다.
관리 모델의 선택 필드 `ManagedCourse.attendanceManagement`와
`attendance-types.ts`, `attendance.ts`가 새 출석 기능을 담당한다.
없는 필드는 기존 v1·v2 동작을 그대로 유지한다. 자동 전환이나 점수→결석 역산은 없다.

**기록의 정의.** `records.total/held`는 총·진행 수업 횟수이며,
`absences/lateness/excused`는 서로 겹치지 않는 별도 사건 횟수이다.
공결을 결석에도 넣지 않는다. 세 사건의 합은 진행 횟수 이하,
진행 횟수는 총 횟수 이하이고 모든 횟수는 0 이상의 안전한 정수이다.
출석 반영비율은 `assessmentId`로 연결한 평가항목의 `weight` 하나만 사용한다.
다른 과목 ID나 과제 그룹은 출석 항목으로 연결할 수 없다.
항목 미연결 또는 0% 배점이어도 미달 규정은 별도로 계산할 수 있다.

**감점.** `penalty`는 규칙 미확인 / 출석 원점수 감점 / 별도 최종 환산 감점이다.
지각은 정수 묶음, 비례, 별도 감점을 직접 선택한다.
공결의 점수 인정 방식도 직접 선택하며 미달 규칙과 공유하지 않는다.
어떤 미확인 정책도 임의의 기본 감점이나 0점으로 메우지 않는다.
확인된 유효 결석에 결석당 감점을 곱하고, 별도 지각 감점이면 그것을 더한다.
원점수 감점은 `출석 배점 × 원점수 감점 / 원점수 만점`으로 환산하고
출석 배점을 넘지 않게 제한한다. 새 `rawMaxScore`를 설정해도 보관된 직접 점수의
기존 만점은 변경하지 않는다. 최종 엔진 연결 때만 점수 비율을 기존 척도로 환산한다.

**4영역.** `per_session_equal`은 회차별 균등 배점이 명시됐음을 사용자가 확인한 경우다.
진행 배점에서 확정 내부 감점을 뺀 만큼만 확보하며, 감점이 진행 배점보다 크면
남은 배점도 그만큼 줄인다. 상실은 언제나 출석 배점 이하다.
감점 규정 미확인이면 진행분은 미확정, 미래분은 남은 배점으로 분류한다.
`term_end` 또는 회차 배점 미확인 상태에서는 진행 중에 확정 감점만 상실로 잡고,
나머지를 진행/미래로 나눌 근거가 없으면 `unclassifiedPoints`로 남긴다.
모든 수업이 끝나고 감점 규칙이 확인돼야 남은 출석 점수를 확보로 확정한다.
`items`는 각 평가항목의 실제 4영역·미분류 내역을 반환하므로 UI에서 재계산하지 않는다.

별도 최종 환산 감점은 출석 배점으로 제한하지 않으며, 다른 평가항목에서 임의로
점수를 차감해 4영역에 섞지 않는다. 4영역은 **별도 최종 감점 전 평가 배점**이다.
`finalDeduction`으로 따로 표시하고, 모든 평가가 확정된 경우에만
`netFinalScore=max(0, secured-finalDeduction)`를 제공한다. 미완료 평가를 가정 점수로 채우지 않는다.

**미달.** `evaluateAttendanceEligibility`는 감점과 독립된 정책을 쓴다.
허용 결석 ‘초과’와 기준 결석 ‘도달’을 명시적으로 구분한다.
최소 출석 비율은 정확히 일치하면 충족이며, 회복 가능한 현재 비율 미달이나
다음 한 번의 결석으로 미달할 경우 위험이다. 남은 수업을 모두 인정받아도
기준에 못 미치면 현재 설정 기준상 미달로 표시한다.
`phase`와 `finalStatus`로 학기 진행 중 판단과 학기 종료 결과를 구분한다.
규정 미확인이면 `needs_review`이며 학교 공통 F 기준을 창조하지 않는다.
시간 기준은 최소 출석 비율에 한해 실제 총·진행·인정시간을 별도 입력받는다.
인정시간에 지각·공결 규정을 반영했다고 확인해야 하며, 횟수로 시간을 추정하지 않는다.

**이전·저장·예측.** 기존 직접 점수와 구 출결 장부는 그대로 보관한다.
새 모드에서는 연결 항목과 새 기록만 반영하고 구 장부를 중복 차감하지 않는다.
`attendanceChangeMessages`가 모드 전환·해제·규칙 변경·횟수 정정을 설명하며,
`saveManagedCourses(courses, snapshot, access?, assignmentConfirmed?, attendanceConfirmed?)`
의 마지막 인수로 명시적 확인이 없으면 보호 대상 변경을 저장하지 않는다.
횟수 증가처럼 새 사실을 추가하는 입력에는 별도 정정 확인이 필요 없다.
저장 실패 시 이전 문서와 편집 중인 내용을 유지하며 v1 키는 쓰지 않는다.
`toEngineCourse`는 출석이 실제로 끝나고 규칙이 확인된 경우에만 정확한 항목 점수를 전달한다.
새 모드일 때 구 장부는 엔진 입력에서 제외한다. 별도 최종 감점은 기존 확률모델에
임의 합성하지 않고 예측을 보류한다. 실제 점수 계산과 미달 판단은 계속 제공한다.

예: 출석 10%, 원점수 만점 100, 총 30회·진행 15회, 별도 결석 2회·지각 3회·공결 1회,
지각 3회=결석 1회, 공결 인정, 결석당 원점수 2점, 명시된 회차별 균등 배점이면
유효 결석 3회, 원점수 감점 6점, 최종 내부 감점 0.6점이다.
출석 부분은 확보 4.4 / 상실 0.6 / 미확정 0 / 남은 배점 5점이다.
미달 기준이 허용 6회 초과라면 현재 정상이며, 정확히 6회는 다음 결석 위험,
7회부터 설정 기준상 미달이다. 실제 F 여부는 적용 규정을 확인한다.

### 잠정 출석 점수 표시

`provisionalAttendanceScore`는 출석 배점에서 현재 확정된 내부 감점만 차감하는 표시용 함수다.
위 예시는 잠정 9.4 / 10점, 내부 감점 -0.6점이다. 미래의 감점은 가정하지 않는다.
이 값을 확보 점수로 전달하지 않으며 4영역 계산·확률모델은 그대로 유지한다.
별도 최종 성적 감점은 잠정 출석 점수에서 빼지 않고 별도로 표시한다.
규칙 미확인·잘못된 입력은 계산을 보류한다. UI의 상세 출석 규칙은 기본 접힘이며
기존 저장 형식과 출결 기록을 변경하지 않는다.

## 16. 학생용 요약·기록·설정

과목 상세는 저장된 데이터의 요약, 일상 기록, 최초 설정을 구분한다. 요약에서는
100점 환산 확보 점수와 네 영역 막대·상태 카드를 우선 표시하고, 계산 근거와
분포 가정에 따른 예측은 접어 둔다. 회색 미분류 배점은 예정이나 0점으로 바꾸지 않는다.
기록·설정 전환은 같은 편집 상태를 사용한다. 요약은 저장된 값만 표시하며
저장 실패 시 편집기는 닫지 않는다. 목록으로 나갈 때는 편집 폐기를 확인한다.

신규 과목은 과목명·학점·반영비율만으로 등록한다. 기존의 명시된 100점 만점과
예정 상태를 화면에서 안내하고, 통계·과제 개수·출석 규칙은 요구하지 않는다.
기존 v1의 null 진행 상태는 이전 검토에서 확인하고, 기존 v2의 null은 설정 편집으로
자동 해소하지 않는다. 저장 가능 여부와 계산·예측 가능 여부는 별도 검증한다.

v2 문서에 선택적인 `semester`, `attendancePreferences`, `attendanceNotes`를 추가한다.
없는 값은 구버전 그대로 읽고 모름으로 표시한다. 학기를 현재 날짜에서 추정하지 않는다.
출석 유형은 예/아니요/모름이며, 유형 답변은 기존 계산 설정을 지우거나 평가비율을
자동 재배분하지 않는다. 미반영 답변과 양의 출석 비율이 공존하면 직접 검토하도록 안내한다.
총·진행 수업 횟수를 모르는 경우에도 별도 출결 횟수를 저장할 수 있다. 이 횟수는
감점·확보점수·미달 판정·확률모델에 넣지 않는다. 규칙 기반 계산 전환은 명시적으로
선택하고 횟수·규칙을 확인한다. 단일 과제는 사용자가 선택하기 전까지 분할하지 않는다.

`course-experience.ts`는 표시용 요약과 선택 필드 검증만 담당한다. `lib/types.ts`나
엔진의 확률 수식은 바꾸지 않는다. 기존 v1 원본과 구버전 v2의 실제 기록을 유지하며,
브라우저 저장 실패와 탭 충돌 처리는 기존 저장 모듈을 재사용한다.

## 17. 이전 데이터 호환 참고 — 규칙 입력형 간편 출석

`simpleAttendance`는 기존 출석 규칙을 재사용하는 선택적 간편 설정이다. 기존 v2에
이 필드가 없으면 상세 출석 계산을 유지하며 자동 전환하지 않는다. 사용자가 유형을
선택하면 `off`(기록·점수 비활성), `record_only`(점수 없이 예외 횟수·위험 관리),
`scored`(출석 항목 점수 반영)를 실제 계산에 적용한다. 기존 `attendanceManagement`,
v1 장부, 직접 점수, 과제·시험은 삭제하지 않는다. 전환·규칙 변경·기록 정정은 기존
저장 확인 절차를 사용한다. 비반영 유형과 양의 출석 비율은 충돌로 검증하며 비율을
자동 재배분하지 않는다. 구버전의 출석 유형 안내 메타데이터는 계산을 덮어쓰지 않는다.

정상 출석의 매회 기록은 요구하지 않는다. 미기록 수업의 정상 출석은 **가정**이며
출석 확인이나 확정 점수의 근거가 아니다. 총·진행 수업 횟수 없이도 예외를 저장하고
점수를 계산한다. 총 수업 횟수·실제 인정시간은 비율 기반 미달 규칙에서만 필요하다.
학기 종료 확정은 별도 사용자 확인이며 미기록·날짜·수업 수로 추정하지 않는다.

출석 배점에서 감점하는 `weighted_points`를 추가해 10점 만점, 결석당 0.2점,
결석 3회일 때 잠정 9.4점·상실 0.6점을 표현한다. 기존 원점수 감점과 최종 성적의
별도 감점 의미는 바꾸지 않는다. 지각·공결이 0회이면 미설정 규칙은 계산을 막지 않는다.
발생했을 때만 해당 규칙을 요구한다. 일부 규칙이 불명확하면 알려진 감점은 상실에
남기고 정확한 잠정 점수는 보류한다. 출석 항목 내부 상실은 그 배점을 초과하지 않는다.

학기 중 기본 출석 배분은 확보 0 / 남은 배점(화면에서는 미확보) 9.4 / 상실 0.6이다.
채점 대기와 앞으로 치를 평가는 내부에서 구분하되 기본 HP바에서는 합쳐 표시한다.
기존 회차별 배점이 있다면 확인된 진행분의 배점 한도를 보존하고 현재 감점을 적용한다.
예외를 추가했다고 진행 수업이나 확보 배점을 자동 증가시키지 않는다. 불명확한
감점이 있으면 나머지를 확보로 단정하지 않는다. 간편 방식과 보관된 장부·직접 점수는
중복 반영하지 않으며 별도 최종 감점은 따로 표시한다. 확률 수학 모델은 변경하지 않는다.

미달 판정은 출석 점수와 독립적이다. 결석 한도의 도달/초과 조건은 설정값 그대로
적용하며, 출석 0%에서도 판정한다. 규정이 없거나 필요한 인정 방식이 미확인이면
F를 추정하지 않는다. 시간 규칙은 실제 확인된 인정시간만 사용한다.

## 18. 현재 출석 UX — 하나의 간이 추정 흐름

현재 화면에서 15·17절의 출석 입력 기능을 제공하지 않는다. `CourseEditor.tsx`의
`AttendanceDraft`, 규칙 변환기, `AttendanceFields`, `SimpleAttendanceFields`, 유형 선택,
공결·시간·미달 기준 폼을 제거했다. `CourseList.tsx`의 이전 `AttendanceStatus` 및
중복 위험 안내도 제거했다. 두 화면은 하나의 `AttendanceEstimateCard`를 재사용한다.
이전 규칙형 신규 생성 함수 `newSimpleAttendance`는 생산 코드에서 제거하고,
과거 저장 형식 회귀 테스트에 필요한 입력 생성만 테스트 내부로 옮겼다.

유일한 현행 저장 입력은 `attendanceEstimate`의 결석·지각이다. 반영비율은 연결된
평가항목을 그대로 읽는다. 원점수·만점·감점량·지각 환산·공결·미달 기준을 입력받지
않는다. 기존 참조 ID 또는 유일한 출석 평가항목을 연결하고, 여러 항목이 모호한 경우
일반 과목 설정에서 정리하도록 안내한다. 비율을 자동 변경하거나 배분하지 않는다.

`attendance-estimate.ts`가 단일 추정 계산과 호환 전환을 담당한다. 모델 이름은
`equal-15-v1`이며 다음 값은 학교의 채점 규정이 아닌 앱의 가정이다.

- 동일한 길이 수업 15회, 지각 3회당 결석 1회
- 유효 결석 = 결석 + floor(지각 / 3)
- 추정 감점 = min(출석 배점, 출석 배점 × 유효 결석 / 15)
- 추정 출석 점수 = max(0, 출석 배점 − 추정 감점)

예: 출석 10점, 결석 3회는 추정 8점이다. 정상 미기록을 출석으로 가정하며 실제
확인 기록으로 표현하지 않는다. 0%·출석 항목 없음은 점수를 숨기고 횟수만 기록한다.
[ERICA 공식 성적처리 안내](https://site.hanyang.ac.kr/web/ehaksa/-grade-process)의
총 수업시간 2/3 출석 기준을 참고한다. 실제 시간 입력이 없으므로 15회 동시간 가정에서
5회 결석은 경계, 6회 이상은 조건부 주의로 표시한다. 시험 응시 제한이나 F를 확정하지
않고, 실제 수업시간과 교수자의 감점 방식에 따라 다를 수 있음을 도움말에 밝힌다.

간이 추정은 `confirmedAttendanceBalance`와 HP바의 확보·상실에 들어가지 않는다.
신규 출석 배점은 모두 미확보다. 기존 확정 기여분만 전환 시 별도 `confirmed`에
보관한다. 결석·지각이 달라져 추정 점수가 변해도 확정 기여분은 바뀌지 않는다.
기존 회차별 확보·직접 점수·별도 최종 감점을 덮어쓰거나 중복 적용하지 않는다.
기존 확률 수식은 바꾸지 않고, 추정 출석을 확정 관측치로 넘기지 않는다.

전환은 읽기 미리보기 → 사용자 저장 확인 → v2 저장 순서다. v1 원본, 기존 장부,
상세·간편 규칙, 공결 기록은 삭제하지 않는다. 공결은 새 감점에 포함하지 않으며,
규칙·점수 의미가 달라지는 전환은 가져올 횟수와 보존 내용을 확인받는다.
기존 `attendance.ts`, `simple-attendance.ts`, `attendance-types.ts`는 이전 데이터의
검증·기여분 복원과 참조 중인 API·회귀 테스트에 필요하므로 유지한다. 현행 UI가
이전 방식의 편집·신규 생성 경로를 다시 제공하지는 않는다. 저장 실패와 탭 충돌은
기존 저장 모듈로 처리하고 편집 내용을 남긴다.

## 19. 수업 횟수·탭 분리·성적 전략 대시보드

`attendanceEstimate.totalSessions`는 선택적 양의 정수다. 구버전 v2에서 필드가 없으면
기존 15회 가정을 그대로 사용한다. 설정 탭에서만 수정하며 학점·시간표로 추정하지
않는다. 기록 탭은 결석·지각 버튼과 현재 N회 가정만 표시한다. 수식은 출석 배점 ×
max(0, 1 − 유효 결석 / N), 최소 필요 출석은 ceil(2N/3), 허용 결석은 floor(N/3)이다.
동일 길이 수업이라는 조건부 모형이며, 남은 여유 2회 이하는 주의, 0회는 경계,
초과는 기준 미달 추정으로 표시한다. 하트는 허용 8회 이하만 개별 표시하고 그 이상은
숫자로 축약한다. 점수 0과 출석 기준 미달·F는 다른 개념이다.

일반 설정 화면에서는 실제 시험·과제 점수/상태와 출결 카운터를 렌더링하지 않는다.
기록 화면에서는 만점·반영비율·과제 구조·통계·수업 횟수를 입력받지 않는다. 동일한
편집 상태를 공유하므로 탭 전환은 데이터를 복제하지 않는다. 기존 v1 이전 검토는
불명확한 실제 상태 확인이 필요하므로 별도의 검토 흐름을 유지한다.

`course-simulation.ts`는 `structuredClone` 복사본과 기존 `transitionAssessment`,
`computeManagedBalance`, `toEngineCourse`, `predict`를 조합한다. 기존 `whatif.ts`의
증감 시나리오는 조건부 기준점수/과거 장부를 사용하므로, 새 N회 출석과 지정 원점수
슬라이더에는 그대로 연결하지 않는다. 확률 수식이나 새 분포 모형을 중복 구현하지 않는다.
현재 등수는 가상 최종 등수로 재사용하지 않는다. 가상 출석은 복사본의 조건부 관측치로만
전달하고 실제 HP·저장 모델에는 기록하지 않는다. 종료·초기화 시 가상 입력을 되돌린다.

이미 확정된 시험은 바꾸지 않고 예정인 단일 평가를 가정한다. 채점 대기와 부분 과제는
앞으로 노력할 시험으로 바꾸거나 0점 처리하지 않는다. 기말 원점수와 출석 가정으로
정해지지 않은 배점은 0~만점 구간으로 남겨 예상 총점 범위를 계산한다. 이전에 출석이
최종 확정된 기록은 가상 결석으로 덮어쓰지 않고, 출석 카드의 간이 변화와 구분한다.
별도 확정 감점은 한 번만 차감하고 0점 하한을 적용한다. 절대 목표 점수의 역산에는
하한 적용 전 합계를 사용해 큰 별도 감점에서도 필요한 점수를 과소 계산하지 않는다.

기존 엔진은 A+, A0, B+, B0, C+, C0, D+, D0, F의 누적확률을 지원한다. 기본 정원은
A 전체 30%, B 전체 40% 및 +/0 절반 배분이라는 가정이다. 실제 학교의 평가 유형별
정원이나 A+/A0 경계를 보장하는 값이 아니다. 조건부 확률은 5% 단위로 표시하고
경계 경고·모델 주의사항을 전달한다. 절대평가·소규모 강좌·정보 부족 시 빈 확률
그래프 대신 점수 계산 결과만 제공한다. 미달 추정 시 시험 응시 제한은 확률에
임의 합성하지 않으며 실제 성적을 F나 0점으로 변경하지 않는다.

`absoluteTargets`는 과목별로 사용자가 확인한 A+/A0/B+/B0의 선택적 100점 환산
기준이다. 기본 95/90점 등을 채우지 않는다. 절대평가이고 기준이 명시됐으며 다른
배점까지 정해진 경우에만 필요한 시험 원점수를 역산한다. 상대평가는 최소 원점수를
확정하지 않고 조건부 누적확률로 비교한다. 가상 입력은 저장하지 않으며 N과 명시한
절대 기준만 기존 v2 문서에 선택 필드로 저장한다. v1 원본과 이전 성적·출결을 유지한다.

## 20. ERICA 공식 프리셋과 목표 우선 플래너

2026-11-07 확인한 [ERICA 공식 성적처리 안내](https://site.hanyang.ac.kr/web/ehaksa/-grade-process)를
`grading-policy.ts`에 버전 고정한다. 상대평가1 A/A+B 상한 30/70%, 상대평가2 40/80%,
상대평가3 50/90%를 지원한다. 이는 실제 부여율도 개인 확률도 아니며 강좌·학기 예외를
확인해야 한다. 절대평가는 최종점수 A+95, A0 90, B+85, B0 80, C+75, C0 70, D+65,
D0 60 이상과 그 미만 F를 기본 표로 제공한다. 공식 표의 A/B/C/D는 앱의 A0/B0/C0/D0로
표기한다. 원점수에 교수자 환산이 있으면 이 합계에 표를 적용한 결과는 조건부다.

공식 P/F 방식에는 모든 강좌에 공통인 합격점이 명시되어 있지 않다. S/U의 70점을
P/F에 적용하지 않는다. P/F 과목은 점수 관리를 계속 지원하며 사용자가 교수자 합격점을
확인해 입력했을 때만 P 목표를 역산한다. 업로드·포털 로그인·과거 분포 자동 수집은 없다.

`gradingPolicy`는 kind, source(official/custom/unconfirmed), presetVersion 및 필요한
사용자 기준만 v2에 추가하는 선택 필드다. 공식과 수정된 기준을 섞어 저장하지 않는다.
우선순위는 새 명시 정책 → 기존 명시 절대평가 기준 → 유형 미확인이다. 구버전의
isAbsolute=false를 상대평가1로 가정하지 않는다. 기존 점수·출결·과제·absoluteTargets는
보존하고, 새 정책은 기록을 해석하는 기준만 바꾼다. 기준이 미확인이어도 저장·점수
범위·목표 총점 플랜은 가능하다. 기존 등수·평균·표준편차를 재활용하며 필수 입력으로
만들지 않는다. 공개된 현재 등수는 현재 전망에만 사용하고 미래 가상 등수로 고정하지 않는다.

기존 예측 미표시 원인은 ① 평균/표준편차 없는 Tier0/1 ② 소규모 강좌 모델 제외
③ 실제 출석 미확정 ④ 부분 과제 집계 미확정이었다. 실제 HP와 확정 예측의 보수적인
연결은 유지하고, 현재 전망은 명시한 예정 평가 가정으로 복사본을 만들어 기존 모델을
사용한다. 상한밖에 없는 상대평가에서 A+/A0를 절반으로 나누지 않는다. 핵심 수식은
그대로 두고 quota 옵션의 A/B 계열 경계만 이용한다. 원래 엔진의 +/0 기본값은 이
프리셋 경로에서 덮어쓰며, A·B 가족 누적확률만 추출한 후 세부 분포는 외부로 반환하지
않는다. 상한을 모두 사용한다는 조건부 비교이지 실제 부여율의 추정이 아니다.
통계·모델 조건이 없으면 확률 대신 점수 범위와 플랜을 제공한다. 빠른 진단 경로는 유지한다.

`grade-planner.ts`는 목표부터 계산한다. 확정된 점수와 출석 가정으로 정해지는
기여분을 목표에서 빼고, 예정 평가의 실제 배점과 원점수 만점으로 역산한다. 개별
과제는 원래 그룹 배점으로 계산하며 부모 점수와 중복 합산하지 않는다. 채점 대기는
미래 노력의 배점으로 바꾸지 않고 0~만점 결과 범위로 유지한다. 미설정 배점은 정밀한
과제별 목표를 생성하지 않는다. 범위의 만점 초과 조건은 불가능하다고 표시한다.

- 균형: 모든 남은 평가에 같은 득점률을 적용
- 과제 우선: 예정 과제를 만점으로 가정한 뒤 시험·기타 필요 점수 계산
- 시험 우선: 예정 시험·기타를 만점으로 가정한 뒤 과제 필요 점수 계산

원점수 추천은 소수 둘째 자리에서 올림해 반올림 때문에 목표에 모자라지 않게 한다.
단일 목표 조합만 유일한 해라고 하지 않는다. 상대평가의 등급별 정확한 최소 점수는
만들지 않고 명시적인 목표 총점으로 전략을 계산한다. 절대평가는 공식 또는 사용자
기준에서 목표를 자동 선택한다. 추가 시험 점수를 먼저 입력할 필요가 없다.

현재 전망은 가능한 범위 및 공개된 비교 가정을 제공한다. 보수적 가정은 최대60%,
낙관적 가정은 최소90%, 현재 유지 가정은 실제 완료 평가의 가중 득점률을 사용한다.
실제 기록이 없으면 현재 유지 시나리오를 생성하지 않는다. 이는 예언이 아닌 비교이며
각 득점률을 표시한다. 기다리는 결과는 여전히 범위다. 출석 가정이 기존 확정 확보·상실
범위를 침범하면 그 확정 범위를 보존한다. 시나리오와 전략은 저장이나 실제 HP를 바꾸지
않는다. 직접 점수를 조작하는 기존 What-if는 상세 분석으로 이동했다.
# 예상 학점 중심 요약

상대평가 헤드라인은 `relative-outlook.ts`의 별도 간이 모델을 사용한다. 평균과
점수 범위만으로 실제 분포는 식별되지 않으므로, [0, 만점]에서 평균을 제약으로 둔
최대엔트로피(절단 지수) 분포를 명시적으로 가정한다. 이는 경험적으로 검증된
학생 점수 분포가 아니며 실제 등수·등급 확률로 해석하지 않는다. 확정 시험의
모형 내 백분위와 반영비율로 시험 기반 위치를 구성하고 미완료 시험은 그 위치
유지를 가정한다. A/B 상한을 모두 사용하고 각각 +/0를 반반 배분한다. 과제·출석은
반 분포가 없어 상대 위치 계산에서 제외하며 총점 계산만 유지한다. C 이하의
세부 비율은 만들지 않는다. 원점수표로 상대평가를 대체하지 않는다.
목표 학점은 동일한 `relativeOutlook` 모형을 기말 점수에 대해 이분 탐색해 역산한다.
기말 평균 미공개 시 기존 확정 시험의 평균 득점률을 환산한 가정임을 표시한다.
필요 점수는 정수로 올림하며 실제 커트라인이 아니다. 다른 미완료 시험은 현재 위치를
유지하고, 채점 대기는 조절할 대상으로 선택하지 않는다. 만점으로도 모형 목표 구간에
닿지 않으면 그 조건에서의 한계를 안내하며 실제 최종 등급 불가로 단정하지 않는다.
평균이 없는 경우 세부 등급을 만들지 않는다. 기존 확률 엔진의 수학은 변경하지 않는다.
아래의 기존 점수표 비교 경로 설명은 이 상대평가 경로로 대체되었다.

요약은 실제 HP바 → 예상 학점과 이유 → 목표 학점별 행동 순서다. 목표 총점 입력과
별도 상세 성적 분석 메뉴는 제거했다. `dashboard-insights.ts`는 시험은 확정 시험 평균,
세부 과제는 해당 그룹의 완료분 평균, 그 외 과제는 확정 과제 평균 득점률을 유지한다.
같은 종류 기록이 없을 때만 전체 확정 평가의 가중 득점률로 대체하고 이를 표시한다.
원점수 만점이 다른 경우 득점률로 정규화한다. 원본 과목을 변경하지 않는다. 확정 기록이
없으면 등급을 만들지 않는다. 채점 대기는 같은 득점률이라는 명시적 가정으로만
헤드라인에 사용하고 목표 전략에서는 조절할 수 없는 결과 범위로 유지한다.

절대평가는 설정된 기준을 사용한다. 상대평가 통계가 있으면 A/B계열 누적 확률이
50% 이상인 가장 높은 계열을 비교 라벨로 사용하며 +/0를 분리하지 않는다.
통계가 부족한 상대평가·평가방식 미확인 과목은 공식 최종점수표의 비교 가정임을
등급 바로 위에 표시한다. 이 경우 목표 전략도 점수표 기준 도전이며 실제 상대평가
커트라인이나 등급 보장이 아니다. 과제 우선은 과제 만점을 조건으로 시험 부담을
비교하며 공부 시간당 효율을 추정하지 않는다. 모든 추정은 실제 HP바와 분리한다.
