# 백테스트 — 4번째 워크스트림 (조율자 담당)

> 회의록 4-6(1) "확정 시 반드시 지킬 것": **기능 구현과 성능 검증은 다른 일이다.**

## 왜 필요한가

앱이 예측한 학점의 정답(실제 성적)은 **발표 이후에 나온다.** 즉 발표 날
"우리 예측이 맞았다"를 보여줄 방법이 구조적으로 없고, 캘리브레이션 화면도 비어 있다.
백테스트가 없으면 이 프로젝트는 아무리 수식이 정교해도 **"그럴듯한 계산기"** 로만 보인다.

동시에, 엔진이 σ를 모를 때 사용하는 κ 프리셋도 **근거가 없으면 숫자로 위장한 추측**이다.

이 모듈은 두 구멍을 같은 데이터로 한 번에 막는다.

## 산출물 2개

### 1. κ 프리셋 근거 (`kappa.ts`)
베타분포에서 `분산 = m(1−m)/(κ+1)` 이므로 역산하면 `κ = m(1−m)/s² − 1`.
과거 시험의 (평균, 표준편차, 만점)만 있으면 κ가 바로 나온다.

**2층 판정을 쓴다:**

| 층 | 조건 | 처리 | 근거 |
|---|---|---|---|
| 1층 | `s² ≥ m(1−m)` | **거부** | 유계 분포에서 수학적으로 불가능 |
| 2층 | `α=mκ<1` 또는 `β=(1−m)κ<1` | 표시 후 집계 제외 | U자형 = 시험 점수로 비현실적 |

회의록의 *"평균 85점 시험에서 σ가 25일 수 없다"* 를 구현하며 확인한 점:
그 조합은 **1층에 안 걸린다.** m=0.85에서 분산 상한은 0.1275라 σ 상한이 35.7점이다.
실제로 걸리는 지점은 2층으로, κ≈1.04가 되어 α<1 → U자형이 된다.
그래서 "불가능"이 아니라 "이 평균에서 그 산포는 이봉분포를 뜻한다"가 정확한 진술이다.
U자형을 거부하지 않고 표시만 하는 이유는, 수강포기자가 많은 과목처럼 **진짜 이봉인
시험이 존재**하기 때문이다. 프리셋 집계에서만 뺀다.

천장 밀집 요소(출석·과제)도 집계에서 제외한다. κ가 수백으로 튀어 시험 프리셋을 오염시킨다.

### 2. 발표용 성능지표 (`run.ts`, `metrics.ts`)

- 정확 적중률 / ±1등급 이내 / 평균 절대오차(등급 단위)
- **80% 구간 포함률** — 이상적으로 80% 근처여야 한다. 95%면 구간이 쓸데없이 넓고,
  50%면 앱이 과신하고 있다는 뜻이다.
- **캘리브레이션** — 화면에 실제로 쓰는 문장(`"A0 이상일 확률 70%"`)을 그대로 검증한다.
  모든 케이스 × 모든 등급의 (예측 누적확률, 실제로 그 등급 이상이었는가) 쌍을 모아
  구간별로 예측 평균 vs 실제 빈도를 비교한다. 표시 형식과 검증 형식이 일치한다.
- Brier score

## 설계상 중요한 두 결정

**(1) blur 케이스를 오답으로 세지 않는다.**
Tier 0~1(표준편차 미공개)에서 엔진은 등급을 단정하지 않는다. 이걸 "틀렸다"로 채점하면
**정직하게 침묵한 엔진이 벌점을 받는다.** `skipped`로 분리하고 제외 건수를 따로 보고한다.

**(2) 헤드라인이 과장하지 않는다.**
회의록은 발표 문구로 *"틀린 건 전부 경계 구간"* 을 제시했지만, 그게 **사실일 때만**
그렇게 쓴다. 아니면 `"틀린 4건 중 1건만 경계 구간으로 사전 표시됨"` 이라고 쓴다.
과장 금지가 이 앱의 정체성인데 발표 문구에서 그걸 깨면 앱 전체의 일관성이 무너진다.
(테스트로 고정: `헤드라인: 오답이 경계구간이 아니면...`)

## 데이터

| 파일 | 용도 |
|---|---|
| `data/backtest.team.json` | **실제 팀원 지난 학기 성적.** 발표 지표는 반드시 이걸로 |
| `data/backtest.sample.json` | 합성 샘플. 하네스 동작 확인 전용 |

⚠ **합성 샘플로는 모델 정확도를 검증할 수 없다.** 생성기가 엔진과 같은 상관구조(ρ=0.6)를
쓰므로 잘 맞는 게 당연하고 아무것도 증명하지 못한다. CLI가 이 경고를 매번 출력한다.

수집할 항목 (과목당): 평가요소별 내 점수·만점·반영비율·**평균·표준편차**, 수강인원,
출결 기록, 그리고 **실제 받은 등급**.

## 실행

```bash
npm run gen:backtest   # 합성 샘플 생성
npm run backtest       # κ 프리셋 + 성능지표
npm test               # 하네스 자체 검증 (8 tests)
```

엔진(`lib/grade`)이 아직 없으면 [1] κ 리포트만 내고 [2]는 건너뛴다.
팀원1의 `predict`가 들어오는 순간 그대로 성능지표가 나온다.

## 현재 상태 (합성 샘플 14건 기준)

```
유효 표본 18건 / 전체 평가요소 36건
사분위  Q1=5.9  중앙값=8.9  Q3=12.9
```
회의록이 예시로 든 *"우리 학교 시험은 보통 κ 5~12"* 와 같은 자릿수지만,
이건 합성 데이터라 **우연의 일치이지 근거가 아니다.** 실제 성적 수집 후 재산출 필요.
